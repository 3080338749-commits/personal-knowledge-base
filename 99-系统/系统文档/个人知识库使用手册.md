# 个人知识库使用手册

## 入口与数据位置

主库：`D:\个人知识库`。在 Obsidian 打开本库，以 [[99-系统/系统文档/个人知识库总仪表盘]] 为入口。原“个人知识库”和原硬件学习中心继续保留。

新增：系统文档、笔记模板、知识回忆、学习记录。科研和硬件沿用原目录；不移动旧笔记或附件。原课程 `D:\课程原始资料\硬件基础篇课程资料` 始终只读。

Codex 最可靠的使用方式是在主库目录打开一个本地项目；新聊天先说“请读取 D:\个人知识库\AGENTS.md”。不会自动继承所有历史聊天，也不会在关闭后自行运行维护。

## 每天开始学习

1. 在 Obsidian 打开统一仪表盘，先看任务与到期复盘。
2. 在主库 Codex 中说“今天开始学习”。Codex 先读历史、未完成测验及当前状态；不能仅凭笔记数量安排已掌握内容。
3. 指明今天想学的主题或论文/章节；若范围已明确直接继续。已有笔记先搜索再打开。
4. 硬件课程以原 JSON 与维护规则为准；研究项目和自由笔记使用新模板及实际来源。

## 每天学习结束

说“今天学习结束，今天学了……，资料是……，范围是第……页”。Codex 会先查重，再增量保存，分区记录原文、AI解释、你的理解及假设。

随后逐题主动回忆，一次一道；你实际回答后才评估。保留首次回答和提示后的回答，不因讲解后听懂而自动升级。没有回答的题不判错、不判掌握。薄弱项加入后续复盘。

硬件仍通过原维护工具的 commit / expected-sha 更新；科研记录保留稳定复盘事件ID。保存后核对差异、更新日志、更新QMD并做本地提交。

## 继续阅读以前的论文

说“继续上次的论文阅读，先读取最近记录，告诉我论文、停点、已读范围和未完成问题”。检索历史后再读原笔记；来源文件找不到时先报告，不能补造内容。

已有两篇论文状态是首轮阅读完成和第二章完成；不是整篇精读均完成。新增精读用 [[99-系统/笔记模板/论文精读模板]]，填写PDF路径、页序与印刷页码、图号；公式符号、实验条件和课题启发分别记录。

## 记录新知识

先在QMD/Obsidian搜索已有标题、别名和概念。已有概念优先追加证据，避免重复创建；新主题才新建笔记。

在目标目录新建Markdown → `Ctrl+P` → “模板：插入模板 / Templates: Insert template” → 选择相应模板。模板文件夹已配置为 `笔记模板`。插入后移除 `template` 标签，填真实来源，未知 mastery 保留 null，按 [[99-系统/系统文档/元数据与掌握度规范]] 填字段。

模板类型：每日学习记录、科研知识点、硬件课程学习、论文精读、专有名词、疑难问题、知识复盘、周学习总结。现有硬件课程优先用其原模板和工具，不用新模板制造第二份课程状态。

## 查看掌握情况与仪表盘

仪表盘的领域笔记数按真实文件查询；不代表掌握数量。新科研体系掌握度0～5，未测为null；硬件原体系0～4，两者分开统计。历史文字评级不强制转换。

科研已测数据、到期 next_review、论文与最近活动来自 Dataview。无记录时显示空表或“无结果”，这是合理空状态；若连示例查询也报红，应检查插件。

硬件“当前学习状态”仍是原生Markdown快照，跨日说“更新学习仪表盘”，Codex按原工具刷新；不能只改快照表格。编辑时间不能当学习时长。

## 任务、复习与卡片

实际学习任务写在原笔记或 [[04-学习记录/学习任务与计划]]，用 `- [ ]`；命令面板 “Tasks: Create or edit task” 可设优先级与到期日。统一首页汇总未完成任务，排除备份、模板和系统文档。没有真实计划时不生成假任务。

科研旧错题见 [[01-科研/光纤论文阅读笔记/光学知识复盘/光学错题与遗忘知识]]，硬件见原错题和复习页。今日人工计划见首页 next_review 查询；旧科研复盘里的文字日期仍须按原记录核对，不假称已结构化导入。

SR：打开 [[04-学习记录/科研回忆卡片]] → `Ctrl+P` → 搜索 “Spaced Repetition” → “Review flashcards in this note”（复习当前笔记卡片）。已建立3张来源明确的示例卡，不代表你已掌握。`问题::答案` 为单行卡片；多行卡片用独立一行 `?` 分隔。卡片间留空行。

回忆后由你按实际表现评分，插件保存自己的调度注释；Codex 的真实答题证据与硬件复习JSON分别维护，不合并重复计数，不擅自改SR评分。勿在其他编辑器清理SR的HTML注释或插件data.json。

## 手动更新QMD与检索

在PowerShell运行（若新终端找不到qmd，使用 `%USERPROFILE%\AppData\Roaming\npm\qmd.cmd`）：

```powershell
qmd --index personal-kb update
qmd --index personal-kb search PGC --json
qmd --index personal-kb search "ASD PSD RMS" --json
qmd --index personal-kb search PMF --json
qmd --index personal-kb get "personal-kb/01-科研/光纤论文阅读笔记/周鑫淼_基于参数估计的光纤水听器PGC解调算法_第二章笔记.md" --full-path
```

关键词搜索不做语义理解，整句中文可能无结果，此时提取缩写/术语，不把无结果解释成库中没有相关知识。

中文向量检索已在科研11篇笔记上完成验收；其余覆盖范围见最新部署报告。使用方式：

```powershell
$env:QMD_LLAMA_GPU = "vulkan"
$env:QMD_EMBED_PARALLELISM = "1"
$env:QMD_EMBED_CONTEXT_SIZE = "1024"
qmd --index personal-kb embed --max-docs-per-batch 1 --max-batch-mb 2
qmd --index personal-kb vsearch "PMF快慢轴如何用于温度补偿" --json
```

也可运行99-系统/系统文档/工具/更新本库索引.ps1；加 -Embed 更新向量，异常时加 -Cpu 使用较慢CPU后备。先 update 再 embed 更新变化笔记的向量。不必每次强制 `-f` 重算全部。未授权下载重排与扩展模型，因此不直接运行普通 `qmd query "..."` 或 `qmd pull`（可能自动下载其他模型）。需要纯结构化混合检索时显式使用 lex/vec 且 `--no-rerank`。

语义索引另排除了硬件08-资料索引中的可再生成大型清单；原清单仍在库内，可用Obsidian/rg检索。

索引配置：`%USERPROFILE%\.config\qmd\personal-kb.yml`；索引数据库位于用户 `.cache\qmd`。它们是可重建检索层，原Markdown才是事实来源。不要在配置中添加 `git pull` 等更新钩子。

## 插件异常

1. 设置 → 第三方插件/社区插件：确认关闭受限模式，四个插件已启用。安装文件存在和启用清单写入不等于已加载，见验收报告真实状态。
2. Dataview：阅读视图打开首页；检查代码块为dataview及元数据类型。默认不启用DataviewJS。按命令面板刷新索引，仍失败先保存错误文本。
3. Tasks：确保任务不在代码块里，查询排除了备份/模板/系统文档；不要为修复样例把全部课程标成任务。
4. SR：确认 `#flashcards/科研` 标签、卡片分隔符、插件启用；模板保持template标签且无flashcards标签。
5. Git：检查 Git 路径和 `git status`；已禁止push。冲突时先备份并比较，不用强制reset。
6. 仅重载异常插件或关闭对应笔记标签后重开；先保护未保存内容，不随意重启全部应用。

QMD出错时先 `qmd --index personal-kb status` 和 `qmd --version`；关键词与向量问题分开处理。索引可重建，原笔记不能随便删。降级可用 `rg -n --glob '*.md' --glob '!**/备份/**' PGC 'D:\个人知识库\01-科研\光纤论文阅读笔记'`，要明确标注是rg。

## 备份、恢复和换电脑

完整流程见 [[99-系统/系统文档/知识库维护与备份指南]]。本地Git保存修改历史，E盘完整副本用于独立恢复；两者用途不同。首次完整备份及恢复抽查记录见 [[99-系统/系统文档/知识库部署及验收报告]]。

新电脑复制完整库和配置后，安装Obsidian及Git/Node/QMD；检查受限模式、插件、CSS和模板设置；更新源路径、QMD collection与MCP命令绝对路径，重建索引并重新验收。不要将本机运行时、桌面PDF路径写死为永久路径。不把备份拷进库内。
