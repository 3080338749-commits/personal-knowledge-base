# 知识库使用与维护指南

> [!tip] 先试一次这三个操作
> 1. 在Obsidian点 [[硬件学习主页]]，再点 [[硬件学习主页]]。
> 2. 在Codex中把 `D:\个人知识库\02-硬件与编程\硬件工程师学习知识库` 添加为本地项目并打开。
> 3. 输入“继续硬件课程学习”，核对它回复的下一单元是 **B01 硬件工程师是干什么的**，进度是 **0/70**。
> 三项核对成功就可以开始；以后不用重发初始化提示词。

## 1. 系统介绍

Obsidian负责阅读、链接、个人补充和展示；Codex在你使用会话时负责讲解、逐题测验、记录与重新计算。Obsidian中的页面是本地文件，不会自动把未保存的聊天变成笔记。

原资料位于 `D:\课程原始资料\硬件基础篇课程资料`，保持只读。资料索引用稳定的SRC标识定位文件；课程目录用B/S/I标识定位学习范围；章节笔记记实际学习内容；知识卡片整理共用概念。测验回答支持掌握等级，错题和复习由真实记录产生。

唯一的学习事实源是 `09-系统配置/学习状态.json`。目录事实来自 `课程目录.json`；资料事实来自 `资料清单.json`。主页、进度、错题表与仪表盘均为派生展示。**直接在仪表盘改数字不会改变事实，后续刷新会重新计算。**

## 2. 第一次如何使用

### 在Obsidian中打开

1. 打开Obsidian，切换到现有库“个人知识库”。如不在此库，点左下方库名称/库切换入口，选择它；如列表中没有，选“打开文件夹作为仓库”，选择 `D:\个人知识库`。
2. 在左侧文件列表展开“硬件工程师学习知识库”→“00-学习中心”。不要将里面的每个子文件夹分别打开为新Vault。
3. 点击“知识库使用与维护指南.md”，即本说明。点击右上方更多操作中的“添加书签”（若界面名称不同，可用命令面板搜索“书签/Bookmark”）。书签是可选核心功能，无需第三方插件。
4. 点击 [[硬件学习主页]] 和 [[硬件学习主页]]。可切到阅读视图看排版；同时按住Ctrl并点击内部链接可打开新标签。手机上通过文件列表找到相同目录。
5. 点击 [[课程路线与总目录]] 查看课程ID、标题和页段；点击 [[章节资料对应表]] 中的文件链接可打开本机资料。E盘链接依赖这台电脑，手机需另行同步资料并配置可访问路径。

### 在Codex中打开正确的工作区

1. 打开Codex桌面应用，在侧栏项目区域使用添加/新建项目并选择本地文件夹。不同版本按钮名称可能不同，关键是最终项目目录为：
   `D:\个人知识库\02-硬件与编程\硬件工程师学习知识库`
2. 在该项目里开启会话。不要只在另一个项目聊天后假定能自动加载此库规则。
3. 输入：

```text
读取当前项目根目录的AGENTS.md，按读取顺序恢复硬件课程学习。先只核对路径、状态版本、总单元数、下一节和到期复习数，不修改学习进度。
```

4. 预期初始化结果：状态版本1、70个映射单元、完成0、下一节B01、到期复习0。课程资料应可访问E盘路径。以后这些数字会随着真实学习改变。
5. 需要确认读写时输入：

```text
检查本知识库和课程资料是否可访问。在09-系统配置内创建并删除一个临时写入探针，不改动原始资料。向我报告实际读写结果。
```

Codex按工作目录层级加载AGENTS规则，规则文件不会使所有任意新聊天自动连上这个Vault。若未加载，显式说“请先读取 D:\个人知识库\02-硬件与编程\硬件工程师学习知识库\AGENTS.md，再继续”。

### 确认保存成功

让Codex汇报状态版本、具体修改文件和校验结果；回到Obsidian查看 [[当前学习状态]] 与仪表盘的同一版本。还可以在资源管理器查看文件修改时间；时间变化本身不能代替内容核对。若Obsidian暂未显示，先重开对应笔记，再检查打开的Vault路径。

## 3. 每天如何开始学习

1. **Obsidian**：打开主页与仪表盘，查看上次快照日期、下一任务和复习队列。
2. **Codex**：打开上述本地项目，在会话中输入：

```text
继续硬件课程学习。读取AGENTS.md和当前学习状态，核对唯一状态数据，按今天的北京时间重算到期复习；先汇报最近进度、未完成测验、今天建议学习范围和资料页码。
```

3. 若有未完成测验，先续答；否则先做优先复习，再开始推荐单元。你可说“今天先学B02的手册解读部分”，Codex应记录实际范围，不把整个单元直接标完成。
4. **PDF阅读器/视频播放器**：打开对应原资料学习。视频不是完整授课录像，只有CIS配置与开机演示；缺资料时先按讲义学习并记录缺口。
5. **Codex**：问题直接问；长讨论中途输入“保存本次已经确认的学习记录，保留未完成任务”。

## 4. 学习过程中如何使用

### 不理解时提问

```text
我正在学习【章节ID、文件与页码】。不理解【问题】。先用直观例子解释，再说明物理机制和适用条件；引用本地资料页码，并区分课件结论与补充解释。请先检查我问题中的前提。
```

### 要更详细的解释

```text
把刚才的【知识点】分步骤讲清楚。先检查我已有理解，再解释每个量和公式的条件，给一个例子让我自己计算；不要直接假定我已掌握。
```

### 结合电路

```text
结合我学过的STM32F103门禁项目，分析【当前讲义页码/电路】的信号路径、工作状态和器件选型。没有提供的电源或器件参数标为待确认，不编造实际电路或测量结果。
```

### 整理当前章节

```text
整理本节笔记，合并本会话已经确认的内容与对应讲义；先查现有章节ID，更新原笔记，保留我的补充和问题。按章节笔记模板写，附来源与页码，不生成其他未学章节。
```

### 保存疑问

```text
记录当前疑难问题：【问题原文】。关联【章节ID/页码】，保留我的理解和待核实条件；如果已有相同问题则追加，不重复建文件。
```

### 补充个人理解

```text
我对【知识点】的理解是：【我的表述】。请先判断正确性，用追问检验。保存时保留我的原文，另写纠正；不要仅凭这句陈述给我标记为已掌握。
```

### 修正已保存错误

```text
【笔记路径/章节ID】中的【原句】可能有误。请核对原资料和适用条件，给出依据后修正；保留必要修订说明，备份原文并同步受影响的知识卡片。不要直接覆盖其他手动内容。
```

## 5. 每次课程结束如何操作

1. 在Codex说“今天学完了”“今天学习完成了”或“这一节学完了”。如会话中范围不清，补充章节ID、页段及是否整节学完。
2. Codex确认本次范围后一次只问一道题，通常5–8题。你先回忆再答；回答错误时先接受提示并再试，保留首次答案和提示后的答案，不混成首次就答对。
3. 想中途停止时说“保存已完成答案，暂停测验，下次继续”。下次说“恢复上一次未完成的学习任务”。未答题不得计错或计正确；进度状态保留“内容学完待测验”。
4. 结束后查看掌握报告：每题表现、尚不能解释的条件、哪些概念需练习。观看课程和能应用是不同记录。
5. 输入：

```text
保存本次课程、测验与复习记录，更新对应笔记、真实错题、薄弱点和间隔复习，再刷新仪表盘。告诉我新状态版本、保存文件、校验结果和下一任务。
```

6. 在Obsidian打开对应章节笔记、[[错题本]]、[[复习计划]]，再看 [[硬件学习主页]]。检查内容确实来自你刚才的回答，不只是聊天里说“已保存”。不要求把所有知识都考到高分才记录课程完成。

## 6. 如何进行每日与阶段复习

| 用途 | 复制到Codex的指令 |
|---|---|
| 每日回忆 | 开始今日复习。读取复习计划并按今天北京时间重算，优先逾期薄弱点和错题，一次一道题；实际作答后更新掌握与下次日期。 |
| 错题复习 | 开始错题复习。只选已学范围内未解决或反复错误的问题，先问原理与条件，不先展示答案，逐题保存。 |
| 每周复盘 | 生成本周学习总结。按北京时间周一至今天统计真实日志，区分课程完成和知识掌握，指出资料缺口，给下周建议并保存总结。 |
| 阶段综合测验 | 进行阶段综合测验。仅使用实际已学内容，先说明范围，一次一道题，兼顾概念、分析和应用；保存未完成状态。 |
| 专项训练 | 针对薄弱知识点【名称/ID】做专项训练，从我实际错因出发逐步追问，结束后保存证据与复习安排。 |

初始目标日期是学习日后1、3、7、14、30天。错题或提示后才会的题，通常缩短到下一天；独立回答稳定时按剩余目标推进。若某个目标已错过，不强行塞入过去日期，记录实际复习日再重排。详细规则见 [[知识库维护规则]]。

只有你在Codex里发起操作时才检查复习。没有后台提醒，也没有自动发送通知的任务。

## 7. 如何手动维护Obsidian知识库

**可以直接写**：章节笔记和知识卡片正文的“我的补充”、实验中的真实记录；派生页面底部“我的补充”也可写。每次刷新会保留标记区外的文字。

**主要交给Codex维护**：学习状态JSON、课程目录JSON、资料清单JSON，以及 `hardware-managed:start/end` 之间的派生表格。不要删改派生标记，不在这些表格里直接纠正统计。

若手动发现进度不符，先在自己的补充区说明日期和真实情况，再输入：

```text
我实际的进度是【说明】。请与日志和唯一状态数据对照，列出差异，只根据我已确认的事实纠正；不得捏造测验答案补齐记录，保留修订历史。
```

新增课程资料：你自行复制到课程目录后，在Codex输入“重新扫描新增课程资料”。它应比较清单和哈希，只解析新增或改变内容；旧文件消失先报错，不删除已有笔记。压缩包不在原目录解包，程序不自动执行。

新增知识卡片前按标题、别名和稳定ID查重，同一个概念优先更新已有卡片。主题相近不代表完全相同，冲突先核实。新增课程单元必须更新课程目录与状态映射，重新说明分母改变原因，不能让完成率变化像学习倒退。

调整结构：优先用Obsidian的重命名/移动并启用内部链接自动更新；涉及JSON里的笔记路径仍需Codex同步检查。大调整前先备份，不批量移动现有论文笔记。

## 8. 如何查看与理解仪表盘

| 指标 | 含义 |
|---|---|
| 模块完成 | 该模块所有映射单元完成才算模块完成 |
| 课程完成率 | 已完成映射单元÷70×100%，等权，不是视频时长或能力分数 |
| 当前章节 | 实际已开始的单元；尚未开始时不把建议章节当当前章节 |
| 已学习知识点 | 有实际学习日期的知识记录数，不是文件数量 |
| 已确认掌握 | 有答题证据的3级或4级知识点 |
| 到期待复习 | 下次复习日期小于或等于统计日期的已学知识点，按知识ID去重 |
| 逾期 | 到期日期早于统计日期；包括在到期待复习总数内 |
| 未解决问题 | 个人疑难问题中未标已解决的条目，资料质量问题另列 |
| 等级分布 | 0未学习、1理解不足、2能解释概念、3独立分析、4综合应用、待评估为缺证据 |
| 最近测验 | 最近保存的测验状态与实际已答题数，中断不冒充完成 |

已完成课程再次出现在复习区是正常的，复习任务与课程内容学习是两回事。尚未拆解的知识点不虚计为0级；初始等级统计全是0表示尚无记录，整体仍待评估。

**维护程序自动计算**：完成率、各等级计数、到期/逾期队列、最近5次日志、入口索引；无需第三方插件。**需在Codex操作时更新**：真实学过的范围、答题原文和判分、纠错、实际实验、掌握判断及复习重排。它们不能从是否看过课程自动推导。

快照不会随午夜自动改变。每天开始时Codex重算一次；只在Obsidian阅读时输入数据不会自动运行维护程序。当前没有安装或要求Dataview；本系统不需要配置它，无插件备用方案就是默认页面本身。

## 9. 换一个Codex会话如何继续

1. 从Codex打开本知识库对应的本地项目，在此项目里新建会话。
2. 输入“继续硬件课程学习”。Codex应先读根AGENTS、当前学习状态、状态JSON、课程地图及当前章节，不重新全盘扫描资料。
3. 核对它报出的版本、上次日期、下一节和未答完题目；与Obsidian当前状态页比对。
4. 旧聊天没保存的讨论不会自动变成持久记忆。能访问旧会话时先在原会话说“保存这次讨论到对应章节”；无法访问时把关键问答复制到新会话，并标注为补录，不能冒充当时测验记录。
5. 若不同文件互相矛盾，说“检查知识库是否存在数据问题”。以状态JSON和原始答题/日志证据核实；派生页旧则重新生成，状态错则先备份再修正。不要仅按最新文件时间选真伪。

## 10. 知识库维护和备份

### 日常备份

每次状态提交/派生刷新前，工具会把当前状态与全部Markdown备份到 `09-系统配置/备份/时间戳`。这些是局部恢复点，和原Vault在同一磁盘，不能替代整库备份。

每周一次、以及批量改结构前：关闭正在编辑的笔记，在资源管理器复制整个 `D:\个人知识库` 到另一磁盘/可靠备份位置，文件夹名附日期。包括 `.obsidian` 配置。原E盘课程资料另行备份；本库仅链接它，不复制全部课程。

### 意外覆盖时恢复

1. 停止继续更新，保留当前文件副本。
2. 找最近一次正确的“备份/时间戳”或外部整库备份，对照受影响文件。
3. 告诉Codex“比较【备份位置】与当前文件，先给差异，恢复我指定的笔记/状态，不覆盖新的个人补充”。
4. 恢复状态后刷新派生页并检查链接；不要只恢复仪表盘而留下不同版本的状态JSON。

Obsidian核心文件恢复功能如已启用也可辅助找回近期版本，但本系统没有替你更改其设置。删除操作能否进回收站取决于当前Obsidian设置，不把它当作可靠备份。

### 重复、链接和路径检查

输入“检查知识库是否存在数据问题”，Codex会检查章节/知识ID、重复标题、内部链接、状态合法性及事务残留。想核对E盘内容变化时补充“同时核对全部源文件哈希”。工具只报告，不删除重复文件。删除、合并或重命名需先看证据和引用。

若课程盘符变了，请提供实际新路径，让Codex验证后更新唯一状态中的源根目录和资料索引链接；不要只替换某个页面。手机未挂载E盘导致资料打不开不意味着笔记丢失。

### 恢复未完成更新

若出现 `待恢复事务.json`，说明一次写入未完整结束。请先看其中备份路径，与当前状态版本比较，让Codex完成派生更新或从同一备份恢复。存在维护锁时先确认没有其他会话正在写入；不要盲删锁或让两会话同时更新。

## 11. 常见问题及解决办法

| 问题 | 操作 |
|---|---|
| Codex忘了进度 | 核对项目路径，显式让它读取根AGENTS与当前学习状态；旧聊天未保存则据你提供的事实补录 |
| 找不到新笔记 | 在Obsidian按文件名搜索，确认Vault路径；在资源管理器确认文件是否实际落盘，重开笔记 |
| 仪表盘没更新 | 在Codex输入“更新学习仪表盘”，核对状态版本与统计日期；不要只修改页面数字 |
| 页面有重复笔记 | 让Codex按ID、内容和来源对比，先备份再处理；检查引用，不直接删名字相似的文件 |
| 资料无法解析 | 打开未解析清单查看所需软件；视频可补字幕；工程用Cadence；未知内容保持未解析 |
| 进度与实际不符 | 说明实际学过的页段与日期，要求对照证据纠正；无测验不补造分数 |
| 双向链接打不开 | 先检查目标是否真实存在及是否改名，运行健康检查；E盘外链另查盘符，不能把文件夹链接当笔记链接 |
| Dataview未安装/报错 | 默认页不用Dataview；直接打开原生仪表盘即可。本库没有任何必须运行的Dataview查询 |
| 复习日期过了仍显示旧数据 | 看快照日期，让Codex按今天北京时间刷新 |
| 维护提示版本冲突 | 先关闭另一会话的写入，重新读取当前状态，合并已确认记录后提交，禁止强行覆盖 |
| 无法运行维护工具 | Codex先探测可用Python3；不要每天重装环境。工具只用标准库，可使用Codex自带运行时；仍不可用就保留状态并明确报告派生页尚未同步 |
| Markdown表格改动被还原 | 你改了生成区；把想保留的内容写在“我的补充”，让Codex改唯一事实源后刷新 |

停用：关闭同名代码片段开关即可恢复原生提示块显示；课程数据和内部链接保留。源代码模式仍会显示Markdown，阅读视图最接近参考图。后续“更新学习仪表盘”会维持本布局。
