# STM32学习笔记：GPIO、结构体指针与寄存器

## 一、今天学到了什么

今天主要理解了：

1. STM32如何使用结构体描述硬件寄存器。
    
2. `GPIOA`和`RCC`为什么是结构体指针表达式。
    
3. `GPIOA->CRL`、`RCC->APB2ENR`是什么意思。
    
4. 寄存器地址偏移和寄存器内部位偏移的区别。
    
5. 如何通过位运算设置、清除和检测寄存器位。
    
6. `GPIO_TypeDef`和`GPIO_InitTypeDef`的区别。
    
7. HAL库如何将用户配置转化为寄存器操作。

# 二、STM32如何访问硬件寄存器

## 1. 寄存器地址由芯片决定

STM32生产出来以后，各个外设寄存器的地址就已经确定了。

程序不负责给寄存器分配地址，只负责按照芯片手册访问这些地址。

例如，STM32F103的GPIOA首地址是：

```
0x40010800
```

GPIOB首地址是：

```
0x40010C00
```

GPIOC首地址是：

```
0x40011000
```

相邻GPIO端口的首地址间隔：

```
0x400字节 = 1024字节
```

```
flowchart LR
    A["GPIOA<br/>0x40010800"] -->|"＋0x400字节"| B["GPIOB<br/>0x40010C00"]
    B -->|"＋0x400字节"| C["GPIOC<br/>0x40011000"]
    C -->|"＋0x400字节"| D["GPIOD<br/>0x40011400"]
```

# 三、GPIO_TypeDef：描述硬件寄存器的排列

STM32头文件中定义了类似下面的结构体：

```
typedef struct
{
    volatile uint32_t CRL;
    volatile uint32_t CRH;
    volatile uint32_t IDR;
    volatile uint32_t ODR;
    volatile uint32_t BSRR;
    volatile uint32_t BRR;
    volatile uint32_t LCKR;
} GPIO_TypeDef;
```

## 1. GPIO_TypeDef是什么

`GPIO_TypeDef`是一个结构体类型名，不是结构体变量。

它的作用是：

> 描述一组GPIO寄存器按照什么顺序排列。

仅仅定义这个结构体类型：

```
typedef struct
{
    /* 成员 */
} GPIO_TypeDef;
```

不会创建变量，也不会为硬件寄存器分配空间。

如果写：

```
GPIO_TypeDef gpio;
```

这时才创建一个普通结构体变量`gpio`，编译器才会为它分配内存。

但STM32访问硬件时通常不会这样做，而是让结构体指针直接指向硬件地址。

---

## 2. GPIOA是什么

STM32头文件大致定义：

```
#define GPIOA ((GPIO_TypeDef *)0x40010800)
```

拆开理解：

```
(GPIO_TypeDef *)0x40010800
```

表示：

> 将硬件地址`0x40010800`解释为一个指向`GPIO_TypeDef`的结构体指针。

因此：

```
GPIOA
```

不是结构体变量，也不是普通指针变量。

严格来说，它是一个宏，展开后得到一个`GPIO_TypeDef *`类型的指针表达式。

可以类比成：

```
GPIO_TypeDef *p = (GPIO_TypeDef *)0x40010800;
```

这里的`p`才是真正的结构体指针变量。

# 四、GPIOA->CRL是什么意思

结构体指针使用`->`访问成员：

```
GPIOA->CRL
```

等价于：

```
(*GPIOA).CRL
```

GPIOA首地址是：

```
0x40010800
```

`CRL`是结构体中的第一个成员，偏移量为：

```
0x00
```

因此：

```
GPIOA->CRL地址
= GPIOA首地址 + CRL成员偏移
= 0x40010800 + 0x00
= 0x40010800
```

各成员的地址如下：

|结构体成员|偏移量|GPIOA中的实际地址|
|---|---|---|
|`CRL`|`0x00`|`0x40010800`|
|`CRH`|`0x04`|`0x40010804`|
|`IDR`|`0x08`|`0x40010808`|
|`ODR`|`0x0C`|`0x4001080C`|
|`BSRR`|`0x10`|`0x40010810`|
|`BRR`|`0x14`|`0x40010814`|
|`LCKR`|`0x18`|`0x40010818`|

因为每个`uint32_t`通常占4字节，所以相邻成员的地址通常相差4字节。

```
flowchart TD
    Base["GPIOA首地址<br/>0x40010800"]
    Base --> CRL["CRL：首地址＋0x00<br/>0x40010800"]
    Base --> CRH["CRH：首地址＋0x04<br/>0x40010804"]
    Base --> IDR["IDR：首地址＋0x08<br/>0x40010808"]
    Base --> ODR["ODR：首地址＋0x0C<br/>0x4001080C"]
    Base --> BSRR["BSRR：首地址＋0x10<br/>0x40010810"]
```

最重要的理解：

> `GPIOA`提供首地址，结构体成员的位置提供偏移量，编译器通过“首地址＋成员偏移”找到寄存器。

# 五、RCC也是结构体指针表达式

RCC结构体简化后类似：

```
typedef struct
{
    volatile uint32_t CR;
    volatile uint32_t CFGR;
    volatile uint32_t CIR;
    volatile uint32_t APB2RSTR;
    volatile uint32_t APB1RSTR;
    volatile uint32_t AHBENR;
    volatile uint32_t APB2ENR;
    volatile uint32_t APB1ENR;
} RCC_TypeDef;
```

RCC首地址：

```
#define RCC ((RCC_TypeDef *)0x40021000)
```

所以：

```
RCC->APB2ENR
```

表示：

```
RCC首地址 + APB2ENR成员偏移
```

`APB2ENR`的偏移量为`0x18`：

```
0x40021000 + 0x18
= 0x40021018
```

因此：

```
RCC->APB2ENR
```

可以近似理解为：

```
*(volatile uint32_t *)0x40021018
```

# 六、地址偏移与位偏移的区别

这是今天最容易混淆的地方。

## 1. 地址偏移

地址偏移用于寻找：

- 哪个GPIO端口；
    
- 哪个寄存器。
    

例如：

```
GPIOA → GPIOB：地址增加0x400字节
CRL → CRH：地址增加4字节
CRH → IDR：地址增加4字节
```

## 2. 位偏移

位偏移发生在已经找到某个32位寄存器以后。

它用于寻找：

- 这个寄存器里的哪一位；
    
- 哪几位属于目标引脚。
    

# STM32 GPIO寄存器与保留位

## 1. GPIO寄存器结构体

```
typedef struct
{
    volatile uint32_t CRL;
    volatile uint32_t CRH;
    volatile uint32_t IDR;
    volatile uint32_t ODR;
    volatile uint32_t BSRR;
    volatile uint32_t BRR;
    volatile uint32_t LCKR;
} GPIO_TypeDef;
```

每个成员都是`uint32_t`：

- 宽度：32位
    
- 大小：4字节
    
- 相邻寄存器地址通常相差4字节
    
- `volatile`表示每次都要真正访问硬件寄存器
    

以GPIOA为例：

```
CRL  ：0x40010800
CRH  ：0x40010804
IDR  ：0x40010808
ODR  ：0x4001080C
BSRR ：0x40010810
BRR  ：0x40010814
LCKR ：0x40010818
```

## 2. 地址偏移与位偏移

- 地址偏移：找到具体寄存器。
    
- 位偏移：找到寄存器内部的具体引脚。
    

```
GPIOA首地址 + 成员偏移 = 寄存器地址
寄存器地址 + 内部位号 = 对应引脚功能
```

注意：引脚不是通过增加字节地址寻找的，而是共享寄存器中的不同位。

## 3. 各寄存器的位分配

|寄存器|作用|位分配|
|---|---|---|
|`CRL`|配置引脚0～7|每个引脚占4位，32位全部使用|
|`CRH`|配置引脚8～15|每个引脚占4位，32位全部使用|
|`IDR`|读取输入电平|低16位对应16个引脚，高16位保留|
|`ODR`|保存输出电平|低16位对应16个引脚，高16位保留|
|`BSRR`|设置或复位输出|低16位置1，高16位清0|
|`BRR`|复位输出|低16位有效，高16位保留|
|`LCKR`|锁定GPIO配置|低17位有效，其余保留|

## 4. 为什么有的引脚占1位，有的占4位

电平只有两种状态：

```
0：低电平
1：高电平
```

所以`IDR`和`ODR`中每个引脚只占1位。

引脚工作模式有很多种，因此`CRL`和`CRH`中每个引脚需要4位：

```
CNF1、CNF0、MODE1、MODE0
```

## 5. BSRR示例

PA5输出高电平：

```
GPIOA->BSRR = (1u << 5);
```

PA5输出低电平：

```
GPIOA->BSRR = (1u << (5 + 16));
```

## 6. 保留位

没有定义用途的位叫作保留位：

```
Reserved bits
```

基本原则：

> 不要随意修改保留位，应按照芯片参考手册操作。

## 核心总结

> GPIO寄存器在地址空间中各占4字节，但寄存器内部的32位如何使用取决于寄存器功能；没有被使用的位称为保留位。

最短记忆：

> 端口和寄存器通过字节地址区分，具体引脚通过寄存器内部的二进制位区分。

# 七、为什么有的引脚相差1位，有的相差4位

因为不同寄存器保存的信息不同。

## 1. ODR、IDR：每个引脚占1位

`ODR`保存引脚输出的高低电平。

一个引脚只有两种电平状态：

```
0：低电平
1：高电平
```

所以每个引脚只需要1位。

```
ODR：

第0位  → PA0输出状态
第1位  → PA1输出状态
第2位  → PA2输出状态
……
第15位 → PA15输出状态
```

因此在`ODR`中：

```
PA1与PA2相差1位
```

设置PA2：

```
GPIOA->ODR |= (1u << 2);
```

## 2. CRL、CRH：每个引脚占4位

GPIO引脚的工作模式有很多种，例如：

- 输入
    
- 推挽输出
    
- 开漏输出
    
- 复用输出
    
- 2 MHz
    
- 10 MHz
    
- 50 MHz
    

所以STM32F103使用4位描述一个引脚的工作模式：

```
CNF1、CNF0、MODE1、MODE0
```

因此每个引脚占4位。

### CRL负责0～7号引脚

```
第0～3位   → PA0配置
第4～7位   → PA1配置
第8～11位  → PA2配置
第12～15位 → PA3配置
第16～19位 → PA4配置
第20～23位 → PA5配置
第24～27位 → PA6配置
第28～31位 → PA7配置
```

### CRH负责8～15号引脚

```
第0～3位   → PA8配置
第4～7位   → PA9配置
第8～11位  → PA10配置
第12～15位 → PA11配置
第16～19位 → PA12配置
第20～23位 → PA13配置
第24～27位 → PA14配置
第28～31位 → PA15配置
```

所以：

```
在ODR中，相邻引脚相差1位。
在CRL/CRH中，相邻引脚的配置区域相差4位。
```

它们并不矛盾，因为讨论的是不同寄存器。

# 八、常用位运算

## 1. 生成位掩码

```
1u << 位号
```

例如：

```
1u << 0   // 0x01
1u << 1   // 0x02
1u << 2   // 0x04
1u << 3   // 0x08
1u << 4   // 0x10
1u << 5   // 0x20
```

`u`表示无符号整数：

```
20      // int
20u     // unsigned int
```

在位运算中使用无符号整数更安全、更清晰。

移位数量不一定要加`u`：

```
0x0Fu << 20
```

是正确写法。

## 2. 将某一位置1

```
value |= mask;
```

例如：

```
value |= (1u << 3);
```

作用：

> 将第3位置1，其他位保持不变。

## 3. 将某一位清0

```
value &= ~mask;
```

例如：

```
value &= ~(1u << 3);
```

作用：

> 将第3位清零，其他位保持不变。

## 4. 检测某一位

```
if ((value & mask) != 0u)
{
    /* 对应位为1 */
}
```

例如：

```
if ((GPIOA->IDR & (1u << 5)) != 0u)
{
    /* PA5输入为高电平 */
}
```

## 5. 同时操作多个位

```
value |= (1u << 2) | (1u << 3);
```

表示同时将第2位和第3位置1。

# 九、开启GPIOA时钟

STM32复位后不会自动给所有外设提供时钟。

使用GPIOA前，需要打开GPIOA时钟：

```
RCC->APB2ENR |= (1u << 2);
```

拆开理解：

```
RCC->APB2ENR
```

找到APB2时钟使能寄存器。

```
1u << 2
```

生成只有第2位为1的掩码。

```
|=
```

将第2位置1，同时保持其他位不变。

不能随便写：

```
RCC->APB2ENR = (1u << 2);
```

因为这样可能把其他已经设置的位清零。

# 十、配置PA5为推挽输出

PA5位于`CRL`的第20～23位。

计算方法：

```
PA5编号 × 每个引脚占4位
= 5 × 4
= 20
```

先清除原配置：

```
GPIOA->CRL &= ~(0x0Fu << 20);
```

其中：

```
0x0F
```

二进制是连续4个1：

```
0000 1111
```

左移20位后覆盖PA5对应的第20～23位。

再写入新配置：

```
GPIOA->CRL |= (0x02u << 20);
```

合并写法：

```
GPIOA->CRL =
    (GPIOA->CRL & ~(0x0Fu << 20)) |
    (0x02u << 20);
```

# 十一、CRL与CRH的偏移计算

## 1. 0～7号引脚

使用`CRL`：

```
shift = pin * 4u;
```

例如PA5：

```
shift = 5u * 4u;
```

结果：

```
shift = 20u;
```

## 2. 8～15号引脚

使用`CRH`，进入`CRH`后重新从第0位计算：

```
shift = (pin - 8u) * 4u;
```

例如PA13：

```
shift = (13u - 8u) * 4u;
```

结果：

```
shift = 20u;
```

因此PA13位于`CRH`的第20～23位。

不是：

```
13 × 4 = 52
```

因为`CRH`是一个新的32位寄存器，需要从第0位重新计算。

# 十二、通过指针选择CRL或CRH

可以使用一个寄存器指针：

```
volatile uint32_t *config_register;
```

如果是0～7号引脚：

```
config_register = &GPIOx->CRL;
```

如果是8～15号引脚：

```
config_register = &GPIOx->CRH;
```

完整示例：

```
void GPIO_ConfigOutput(GPIO_TypeDef *GPIOx, uint32_t pin)
{
    volatile uint32_t *config_register;
    uint32_t shift;

    if (pin > 15u)
    {
        return;
    }

    if (pin < 8u)
    {
        config_register = &GPIOx->CRL;
        shift = pin * 4u;
    }
    else
    {
        config_register = &GPIOx->CRH;
        shift = (pin - 8u) * 4u;
    }

    *config_register =
        (*config_register & ~(0x0Fu << shift)) |
        (0x02u << shift);
}
```

如果调用：

```
GPIO_ConfigOutput(GPIOC, 13u);
```

则：

```
GPIOx = GPIOC
config_register = &GPIOC->CRH
shift = (13 - 8) × 4 = 20
```

所以：

```
*config_register
```

相当于：

```
GPIOC->CRH
```

# 十三、GPIO_TypeDef与GPIO_InitTypeDef

这是HAL库中非常重要的两类结构体。

## 1. GPIO_TypeDef：硬件地址地图

```
typedef struct
{
    volatile uint32_t CRL;
    volatile uint32_t CRH;
    volatile uint32_t IDR;
    volatile uint32_t ODR;
    volatile uint32_t BSRR;
    volatile uint32_t BRR;
    volatile uint32_t LCKR;
} GPIO_TypeDef;
```

它的作用：

> 描述硬件寄存器如何排列。

典型对象：

```
GPIOA
GPIOB
GPIOC
```

访问方式：

```
GPIOA->CRL
```

它会真正访问芯片寄存器。

## 2. GPIO_InitTypeDef：用户配置申请表

HAL库中简化后的定义：

```
typedef struct
{
    uint32_t Pin;
    uint32_t Mode;
    uint32_t Pull;
    uint32_t Speed;
} GPIO_InitTypeDef;
```

定义普通结构体变量：

```
GPIO_InitTypeDef config;
```

填写配置：

```
config.Pin   = GPIO_PIN_5;
config.Mode  = GPIO_MODE_OUTPUT_PP;
config.Pull  = GPIO_NOPULL;
config.Speed = GPIO_SPEED_FREQ_LOW;
```

`config`只是一个普通RAM变量，并不会直接修改硬件。

## 3. 两者对比

|   |   |   |
|---|---|---|
|项目|`GPIO_TypeDef`|`GPIO_InitTypeDef`|
|作用|描述硬件寄存器|保存用户配置|
|类比|硬件地址地图|配置申请表|
|典型对象|`GPIOA`|`config`|
|对象形式|固定硬件地址的指针表达式|普通结构体变量|
|访问方式|`GPIOA->CRL`|`config.Pin`|
|是否直接访问硬件|是|否|
|是否通常带`volatile`|是|否|

# 十四、HAL_GPIO_Init如何连接两者

调用：

```
HAL_GPIO_Init(GPIOA, &config);
```

函数原型类似：

```
void HAL_GPIO_Init(GPIO_TypeDef *GPIOx,
                   GPIO_InitTypeDef *GPIO_Init);
```

参数含义：

```
GPIOA
→ 告诉HAL要配置哪个硬件端口

&config
→ 告诉HAL具体希望怎样配置
```

进入函数后可以近似理解为：

```
GPIO_TypeDef *GPIOx = GPIOA;

GPIO_InitTypeDef *GPIO_Init = &config;
```

HAL通过：

```
GPIO_Init->Pin
GPIO_Init->Mode
GPIO_Init->Pull
GPIO_Init->Speed
```

读取用户配置。

然后通过：

```
GPIOx->CRL
GPIOx->CRH
```

修改真正的硬件寄存器。

```
flowchart LR
    A["普通RAM变量<br/>GPIO_InitTypeDef config"]
    B["填写配置<br/>Pin、Mode、Pull、Speed"]
    C["HAL_GPIO_Init<br/>GPIOA, &config"]
    D["HAL通过GPIO_Init指针<br/>读取用户配置"]
    E["HAL计算寄存器和位掩码"]
    F["通过GPIOx指针<br/>修改GPIOA->CRL或CRH"]
    G["真实GPIO硬件配置改变"]

    A --> B --> C --> D --> E --> F --> G
```

一句话总结：

> `GPIO_InitTypeDef`保存“想怎么配置”，`GPIO_TypeDef`帮助HAL找到“应该写到哪个硬件地址”。

# 十五、完整底层示例

将PA0配置为推挽输出并输出高电平：

```
#include <stdint.h>

#define RCC_APB2ENR (*(volatile uint32_t *)0x40021018u)
#define GPIOA_CRL   (*(volatile uint32_t *)0x40010800u)
#define GPIOA_BSRR  (*(volatile uint32_t *)0x40010810u)

int main(void)
{
    /* 打开GPIOA时钟 */
    RCC_APB2ENR |= (1u << 2);

    /* PA0配置为2 MHz推挽输出 */
    GPIOA_CRL =
        (GPIOA_CRL & ~0x0Fu) |
        0x02u;

    /* PA0输出高电平 */
    GPIOA_BSRR = (1u << 0);

    while (1)
    {
    }
}
```

使用结构体后的写法：

```
RCC->APB2ENR |= (1u << 2);

GPIOA->CRL =
    (GPIOA->CRL & ~0x0Fu) |
    0x02u;

GPIOA->BSRR = (1u << 0);
```

两种写法最终都在操作相同的硬件地址。

# 十六、今天最容易犯的错误

## 错误1：认为GPIOA是结构体变量

错误：

```
GPIOA是GPIO_TypeDef结构体变量
```

正确：

```
GPIOA是GPIO_TypeDef *类型的结构体指针表达式
```

---

## 错误2：认为结构体给寄存器分配地址

错误：

```
结构体成员依次给寄存器分配地址
```

正确：

```
寄存器地址由芯片决定。
结构体成员的位置只是帮助编译器计算地址偏移。
```

---

## 错误3：认为PA1和PA2有各自的寄存器地址

错误：

```
PA1和PA2的地址相差几个字节
```

正确：

```
PA1和PA2通常共享同一个寄存器地址，
只是占据寄存器中的不同位。
```

---

## 错误4：把引脚编号当成引脚掩码

```
3u
```

表示引脚编号3。

```
1u << 3
```

才表示第3位为1的位掩码。

HAL中的：

```
GPIO_PIN_3
```

通常等于：

```
(uint16_t)(1u << 3)
```

也就是：

```
0x0008
```

# 十七、今日核心总结

```
GPIO_TypeDef
→ 描述硬件寄存器排列

GPIOA
→ 指向GPIOA硬件首地址的结构体指针表达式

GPIOA->CRL
→ GPIOA首地址加CRL成员偏移

寄存器地址偏移
→ 用来找到端口和寄存器

寄存器内部位偏移
→ 用来找到具体引脚

GPIO_InitTypeDef
→ 保存用户希望使用的配置

HAL_GPIO_Init(GPIOA, &config)
→ 将用户配置转换为真正的寄存器操作
```

最终理解：

> STM32底层开发仍然是普通的C语言。结构体描述寄存器布局，指针保存硬件地址，成员偏移找到寄存器，位运算修改寄存器中的具体配置位，HAL库则把这些底层操作封装成更容易使用的函数。
