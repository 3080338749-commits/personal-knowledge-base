# Day 3：指针与STM32内存映射

## 1. 指针基础

```
uint32_t value = 10u;
uint32_t *p = &value;
```

```
p       保存value的地址
*p      访问value中的数据
&p      取得指针变量p自身的地址
&value  取得value的地址
```

关系：

```
p == &value
*p == value
```

修改：

```
*p = 30u;
```

相当于通过地址把`value`修改为30。

> `p`得到地址，`*p`才是访问该地址中的数据。

---

## 2. 指针自身的大小

在STM32F103的32位环境中，常见数据指针通常都是4字节：

```
sizeof(char *)      // 通常4
sizeof(uint16_t *)  // 通常4
sizeof(uint32_t *)  // 通常4
sizeof(float *)     // 通常4
```

原因：它们保存的都是32位地址。

指针类型不决定指针自身大小，而是决定：

- 解引用时访问多少字节；
    
- 指针加1时跨过多少字节；
    
- 如何解释地址中的数据。
    

```
uint8_t  *p：*p访问1字节
uint16_t *p：*p访问2字节
uint32_t *p：*p访问4字节
```

---

## 3. 指针加1的含义

```
新地址 = 原地址 + sizeof(指向的类型)
```

假设初始地址为`0x20000000`：

```
uint8_t  *p：p + 1 = 0x20000001
uint16_t *p：p + 1 = 0x20000002
uint32_t *p：p + 1 = 0x20000004
```

> 指针加1不是固定增加一个字节，而是移动到下一个同类型对象。

---

## 4. 数组与指针

```
uint16_t data[3] = {100u, 200u, 300u};
uint16_t *p = data;
```

```
p          == &data[0]
*p         == data[0]
*(p + 1)   == data[1]
*(p + 2)   == data[2]
```

数组下标本质：

```
p[i] == *(p + i)
```

注意数组使用方括号：

```
data[1]  // 正确
data{1}  // 错误
```

---

## 5. STM32固定地址指针

```
volatile uint32_t *reg =
    (volatile uint32_t *)0x40021018u;
```

逐部分理解：

```
0x40021018u
普通无符号整数地址值

(volatile uint32_t *)0x40021018u
把整数地址转换成32位寄存器指针

reg
保存寄存器地址

*reg
访问该地址上的32位寄存器数据
```

关系图：

```
reg保存0x40021018
        │
        ▼
┌────────────────────┐
│ APB2ENR寄存器数据  │
└────────────────────┘
```

> 强制转换只是把数字解释为指针，不会创建寄存器，也不会分配内存。

---

## 6. 寄存器读写

读取寄存器：

```
uint32_t value = *reg;
```

直接写入整个寄存器：

```
*reg = 5u;
```

修改某一位：

```
*reg |= 1u << 2u;
```

`|=`的完整过程：

```
读取寄存器
→ 与掩码进行按位或
→ 把结果写回寄存器
```

在STM32F103中：

```
*(volatile uint32_t *)0x40021018u |= 1u << 2u;
```

表示：

```
找到APB2ENR寄存器
→ 读取寄存器
→ 将第2位置1
→ 写回寄存器
→ 开启GPIOA时钟
```

---

## 7. `volatile`的作用

```
volatile uint32_t *reg;
```

`volatile`告诉编译器：

> 该地址中的数据可能被硬件或中断改变，每次读写都必须真正访问内存。

读取：

```
uint32_t value = *reg;
```

必须真正读取硬件寄存器。

写入：

```
*reg = 5u;
```

必须真正写入硬件寄存器。

容易混淆：

```
volatile不表示“每次写入前必须读取”。
```

下面代码会先读再写，是因为使用了`|=`：

```
*reg |= mask;
```

而不是因为使用了`volatile`。

`volatile`也不保证：

- 操作不会被中断；
    
- 多步操作是原子的；
    
- 程序自动变得线程安全。
    

---

## 8. 访问宽度

```
volatile uint8_t  *p8;   // 解引用访问1字节
volatile uint16_t *p16;  // 解引用访问2字节
volatile uint32_t *p32;  // 解引用访问4字节
```

`APB2ENR`是32位寄存器，所以应该使用：

```
volatile uint32_t *
```

指针类型必须与硬件寄存器宽度匹配。

---

## 9. 地址对齐

`uint32_t`访问通常要求地址是4的整数倍：

```
0x20000000  正确
0x20000004  正确
0x20000008  正确

0x20000001  未对齐
0x20000002  未对齐
0x20000003  未对齐
```

错误或未对齐的地址可能：

- 降低访问效率；
    
- 访问错误的数据；
    
- 触发HardFault。
    

寄存器地址必须来自：

- 芯片参考手册；
    
- 官方头文件；
    
- 芯片数据手册。
    

不能随便猜测。

---

## 10. 空指针

```
uint32_t *p = NULL;
```

在STM32F103中，`p`通常仍占4字节。

`NULL`表示：

```
指针变量p存在
但没有指向有效对象
```

不能解引用：

```
*p = 20u; // 错误，可能触发HardFault
```

安全检查：

```
if (p != NULL)
{
    *p = 20u;
}
```

> 空指针不是“不占空间”，而是“没有有效指向”。

---

## 11. 重点记忆

```
p保存地址，*p访问数据，&p取得p自身的地址。

指针通常都是4字节，
指针类型决定访问宽度和移动步长。

强制转换只改变地址的解释方式，
不会创建内存或寄存器。

volatile保证真实访问内存，
不等于写入前自动读取。

*reg |= mask：
读取 → 修改 → 写回。

空指针仍然存在并占空间，
但不能解引用。
```
# Day 4：结构体与STM32寄存器映射

## 1. 结构体类型、变量和指针

```
typedef struct
{
    uint32_t x;
    uint32_t y;
} Point_TypeDef;

Point_TypeDef point;
Point_TypeDef *p = &point;
```

区别：

```
Point_TypeDef  → 结构体类型名称
point          → 结构体变量
p              → 指向结构体变量的指针
```

访问成员：

```
point.x = 10u; // 结构体变量使用 .
p->x = 20u;   // 结构体指针使用 ->
```

等价关系：

```
p->x == (*p).x
```

记忆：

```
变量本体用 .
结构体指针用 ->
```

---

## 2. 结构体成员偏移

```
typedef struct
{
    uint32_t CRL;
    uint32_t CRH;
    uint32_t IDR;
    uint32_t ODR;
    uint32_t BSRR;
} GPIO_TypeDef;
```

每个`uint32_t`占4字节：

```
成员    十进制偏移    十六进制偏移
CRL         0             0x00
CRH         4             0x04
IDR         8             0x08
ODR        12             0x0C
BSRR       16             0x10
```

第一个成员偏移是`0`，不是`4`。

计算公式：

```
成员偏移 = 该成员前面所有成员占用的字节数
```

---

## 3. 地址偏移不是位编号

```
偏移0x08 = 十进制8 = 向后移动8字节
```

换算为二进制距离：

```
8字节 × 8位 = 64位
```

但内存地址以字节为单位，所以仍写成：

```
首地址 + 0x08
```

必须区分：

```
首地址 + 0x08  → 在内存中向后移动8字节
1u << 8u       → 选择寄存器内部的第8位
```

这两个“8”不是同一个概念。

---

## 4. 结构体映射GPIO寄存器

```
#define GPIOA_BASE 0x40010800u
#define GPIOA ((GPIO_TypeDef *)GPIOA_BASE)
```

区别：

```
GPIO_TypeDef → 描述寄存器排列的结构体类型
GPIOA_BASE   → GPIOA硬件首地址
GPIOA        → 指向该地址的结构体指针表达式
```

访问：

```
GPIOA->ODR
```

编译器计算：

```
GPIOA首地址：0x40010800
ODR偏移：   +0x0000000C
----------------------
实际地址：  0x4001080C
```

所以：

```
GPIOA->ODR
```

可理解为：

```
*(volatile uint32_t *)0x4001080Cu
```

核心公式：

```
寄存器实际地址 = 外设首地址 + 结构体成员偏移
```

> 结构体不会给寄存器分配地址，只负责描述成员偏移。

---

## 5. `RESERVED`保留成员

假设硬件布局：

```
偏移0x00 → CTRL
偏移0x04 → 保留
偏移0x08 → STATUS
```

结构体：

```
typedef struct
{
    volatile uint32_t CTRL;
    uint32_t RESERVED;
    volatile uint32_t STATUS;
} Device_TypeDef;
```

`RESERVED`占据4字节空隙，使`STATUS`保持在正确的`0x08`偏移。

```
偏移0x00 → CTRL
偏移0x04 → RESERVED
偏移0x08 → STATUS
```

> `RESERVED`只用于占位置，不应主动读写。

---

## 6. 结构体对齐与填充

```
typedef struct
{
    uint8_t  a;
    uint32_t b;
} Example;
```

常见布局：

```
偏移0 → a，占1字节
偏移1 → 填充
偏移2 → 填充
偏移3 → 填充
偏移4 → b，占4字节
```

因此通常：

```
offsetof(Example, a) // 0
offsetof(Example, b) // 4
sizeof(Example)      // 8
```

为什么有3个填充字节？

> `uint32_t b`通常需要从能被4整除的地址开始。

查看偏移：

```
#include <stddef.h>

offsetof(Example, b);
```

结构体大小包含填充字节。

---

## 7. `__IO`与`volatile`

STM32头文件常见写法：

```
__IO uint32_t ODR;
```

`__IO`通常等价于：

```
volatile uint32_t ODR;
```

简单理解：

```
__I  → 主要读取
__O  → 主要写入
__IO → 可以读取和写入
```

`volatile`要求每次读写都真正访问硬件寄存器。

---

## 8. 普通结构体与硬件寄存器

普通结构体变量：

```
GPIO_TypeDef gpio_copy;
gpio_copy.ODR = 5u;
```

修改的是RAM中的普通变量。

硬件结构体指针：

```
GPIOA->ODR = 5u;
```

修改的是真实GPIOA硬件寄存器。

```
GPIO_TypeDef gpio_copy
→ 在RAM中创建普通结构体

(GPIO_TypeDef *)0x40010800u
→ 不创建结构体，只用结构体布局解释硬件地址
```

---

## 9. 重点记忆

```
结构体变量用 .
结构体指针用 ->

第一个结构体成员偏移为0。

地址偏移以字节为单位，
寄存器位编号以二进制位为单位。

寄存器地址 =
外设首地址 + 成员偏移。

RESERVED用于占住硬件地址空隙。

结构体可能因对齐产生填充字节。

GPIO_TypeDef描述布局，
GPIOA提供硬件首地址，
GPIOA->成员访问真实寄存器。
```
