# Day15：const、volatile、static与中断共享变量

## 1. static

### 局部static变量

```
void Add(void)
{
    static uint32_t count = 0;
    count++;
}
```

特点：

- 只在函数内部可见；
- 只初始化一次；
- 函数结束后数值不会消失；
- 下次调用继续使用上次的值。

### 文件级static变量

```
static uint32_t count = 0;
```

表示`count`只允许当前`.c`文件直接使用，适合保存模块私有数据。

---

## 2. const指针

```
const int *p1;             // 不能通过p1修改数据，p1可以换指向
int * const p2 = &value;   // 可以修改数据，p2不能换指向
const int * const p3 = &value; // 数据和指向都不能修改
```

记忆方法：

```
const在*左边：限制目标数据
const在*右边：限制指针自己
```

---

## 3. volatile

```
volatile uint32_t count = 0;
```

表示`count`可能被中断或硬件突然改变，程序每次使用时都必须真正访问内存。

但是`volatile`不能保证操作不会被打断。

```
count++;
```

实际包含：

```
读取count
→ 加1
→ 写回count
```

因此：

> `volatile`保证真正读写，但不保证原子性或线程安全。

---

## 4. 事件标志与计数器

事件标志：

```
event = 1;
event = 1;
event = 1;
```

最终仍然是：

```
event = 1
```

它只能表示“至少发生过一次”，不能表示发生了几次。

需要记录次数时使用：

```
count++;
```

---

## 5. 重点：为什么会丢失计数

假设：

```
count = 5
```

执行顺序：

```
主程序：result = count     → result = 5
中断：  count++            → count = 6
主程序：count = 0          → count = 0
```

中断新增加的第6次计数被清零覆盖，因此丢失。

---

## 6. 使用临界区保护

```
uint32_t Take_Count(void)
{
    uint32_t old_irq;
    uint32_t result;

    old_irq = __get_PRIMASK();
    __disable_irq();

    result = count;
    count = 0;

    __set_PRIMASK(old_irq);

    return result;
}
```

真正需要一起保护的是：

```
result = count;
count = 0;
```

关闭中断后，新中断暂时不能插入这两句之间。

恢复中断后，等待的中断再执行：

```
关闭中断
→ 取走旧计数
→ count清零
→ 恢复中断
→ 新中断执行count++
```

新计数进入下一轮，不会丢失。

必须恢复原状态：

```
__set_PRIMASK(old_irq);
```

不能无条件使用：

```
__enable_irq();
```

因为进入函数前，中断可能本来就是关闭的。

---

## 7. 缓冲区与临界区的区别

这是本次最容易混淆的地方。

```
缓冲区：保存多个数据或事件
临界区：保护一组操作不被中断插入
```

建立缓冲区可以改变事件的保存方式，但不能直接保证：

```
result = count;
count = 0;
```

不会被中断从中间打断。

这段计数程序最直接的解决办法是临时关闭中断。

---

## 8. const volatile

```
const volatile uint32_t *status;
```

表示：

```
const：软件不能通过status修改目标数据
volatile：目标数据可能被硬件改变，每次必须重新读取
```

常用于只读硬件状态寄存器。

---

## 9. EXTI计数流程

```
PA0出现上升沿
→ EXTI0_IRQHandler
→ HAL_GPIO_EXTI_IRQHandler
→ HAL_GPIO_EXTI_Callback
→ count++
```

中断只负责快速计数：

```
void HAL_GPIO_EXTI_Callback(uint16_t pin)
{
    if (pin == GPIO_PIN_0)
    {
        count++;
    }
}
```

主程序每秒安全取走计数，再执行报警等复杂处理。

---

## 10. 指针强转并解引用是什么意思

假设接收数组为：

```
uint8_t rx[5] =
{
    0xAA,
    0x12,
    0x34,
    0x56,
    0x78
};
```

代码：

```
uint32_t value;
value = *(uint32_t *)&rx[1];
```

需要从内向外理解。

### 第一步：找到数组元素

```
rx[1]
```

表示数组的第二个字节，当前值为`0x12`。

### 第二步：取得地址

```
&rx[1]
```

取得`rx[1]`所在的内存地址。此时地址类型为`uint8_t *`，正常情况下通过它只读取1字节。

### 第三步：改变指针类型

```
(uint32_t *)&rx[1]
```

把这个地址强制解释成`uint32_t *`，意思是以后从该地址按照4字节数据读取。

强制转换不会移动数据、不会交换字节，也不会修改数组，只改变程序看待这个地址的方式。

### 第四步：解引用

```
*(uint32_t *)&rx[1]
```

最前面的`*`表示真正访问该地址，从`rx[1]`开始连续读取4字节：

```
rx[1]  rx[2]  rx[3]  rx[4]
 12      34     56     78
```

整句可以拆成：

```
uint8_t *p8 = &rx[1];
uint32_t *p32 = (uint32_t *)p8;
value = *p32;
```

在STM32小端环境中，内存中的`12 34 56 78`直接作为32位整数读取，结果通常被解释为：

```
value = 0x78563412;
```

记忆：

```
&rx[1]       ：找到0x12所在的位置
(uint32_t *) ：要求从这里按照4字节读取
*            ：真正读取这4个字节
value =      ：把读取结果保存到value
```

这种写法不推荐用于通信解析，因为：

- `&rx[1]`可能没有按4字节对齐；
- 读取结果受到CPU大小端影响；
- 直接转换并解引用还可能涉及C语言的类型访问规则。

更可靠的方式是按照通信协议逐字节移位组合。

---

## 核心总结

```
static：保存变量或限制文件访问范围
const：限制修改
volatile：保证真实访问
临界区：防止一组操作被中断插入
缓冲区：保存多个数据或事件
```

最重要的一句话：

> `volatile`解决“必须重新读写”，临界区解决“这几步不能被中断拆开”。
# Day16：内存对齐、大小端与通信数据

## 1. 多字节整数

```
uint32_t value = 0x12345678;
```

`uint32_t`占4字节，可以拆成：

```
12 34 56 78
```

其中：

```
12：最高字节
78：最低字节
```

---

## 2. STM32小端存储

STM32通常采用小端：

```
低地址保存最低字节
```

因此`0x12345678`在内存中排列为：

```
低地址 → 78 56 34 12 → 高地址
```

但变量的数值仍然是：

```
0x12345678
```

### 重点：三种顺序

```
数值写法：12 34 56 78
小端内存：78 56 34 12
通信顺序：由协议决定
```

如果协议规定高字节先发：

```
12 34 56 78
```

如果协议规定低字节先发：

```
78 56 34 12
```

> 小端只决定内存摆放，协议决定通信发送顺序。

---

## 3. 拆分32位整数

高字节先发送：

```
tx[0] = (uint8_t)(value >> 24);
tx[1] = (uint8_t)(value >> 16);
tx[2] = (uint8_t)(value >> 8);
tx[3] = (uint8_t)value;
```

如果：

```
value = 0x12345678;
```

那么：

```
tx = 12 34 56 78
```

强制转换成`uint8_t`后，只保留最低8位。

---

## 4. 组合32位整数

```
value = ((uint32_t)rx[0] << 24)
      | ((uint32_t)rx[1] << 16)
      | ((uint32_t)rx[2] << 8)
      |  (uint32_t)rx[3];
```

如果：

```
rx = 12 34 56 78
```

组合过程：

```
12 → 12000000
34 → 00340000
56 → 00005600
78 → 00000078
```

按位或后：

```
value = 0x12345678
```

这里是代码主动安排字节位置，因此不受STM32小端内存顺序影响。

---

## 5. 原始字节与整数数值

这是本次容易混淆的地方。

```
56 78
```

表示两个独立字节。

组合以后：

```
0x5678
```

表示一个16位整数。

同理：

```
11 22 33 44    → 四个原始字节
0x11223344     → 一个32位整数
```

---

## 6. 内存对齐

常见STM32对齐规则：

```
uint8_t：占1字节，按1字节对齐
uint16_t：占2字节，按2字节对齐
uint32_t：占4字节，按4字节对齐
```

结构体：

```
typedef struct
{
    uint32_t value;
    uint16_t id;
    uint8_t status;
} Message_t;
```

布局：

```
偏移0～3：value
偏移4～5：id
偏移6：status
偏移7：尾部填充
```

因此：

```
value偏移 = 0
id偏移 = 4
status偏移 = 6
sizeof(Message_t) = 8
```

### 重点：大小与对齐不是一回事

```
类型大小：成员占几个字节
对齐要求：成员从哪个偏移开始
```

`uint16_t id`仍然只占2字节，不会因为结构体按4字节对齐就变成4字节。

---

## 7. packed结构体

```
typedef struct __attribute__((packed))
{
    uint16_t id;
    uint32_t value;
    uint8_t status;
} PackedMessage_t;
```

取消填充后：

```
id偏移 = 0
value偏移 = 2
status偏移 = 6
sizeof = 7
```

但是`value`从偏移2开始，不满足4字节对齐。

```
packed可以取消填充
packed不能解决大小端
packed可能产生未对齐访问
```

因此，不能把`packed`当成通用通信协议解决方案。

---

## 8. 不要随便强转通信数组

危险写法：

```
value = *(uint32_t *)&rx[1];
```

如果：

```
rx首地址 = 0x20000000
&rx[1] = 0x20000001
```

`0x20000001`不满足4字节对齐。

另外，小端直接读取：

```
内存字节：12 34 56 78
得到数值：0x78563412
```

因此可能存在：

- 地址未对齐；
- 大小端错误；
- 编译器和平台兼容问题。

更可靠的方式是逐字节移位组合。

---

## 9. 数组容量与有效长度

```
uint8_t rx[7];
uint32_t length = 5;
```

表示：

```
数组容量 = 7字节
这次实际收到 = 5字节
```

解析7字节消息以前必须检查：

```
if (length < 7)
{
    return;
}
```

数组有7格，不代表这次7格里都有有效通信数据。

---

## 10. 通信的本质

UART、I²C、SPI在线路上传输的是字节，不会自动传输：

```
变量名
C语言类型
变量占多少字节
大小端信息
```

完整过程：

```
发送端变量
→ 按协议拆成字节
→ 发送字节数组
→ 接收字节数组
→ 检查有效长度
→ 按协议组合
→ 接收端变量
```

## 核心总结

```
小端：决定内存中字节怎么放
对齐：决定成员从哪个地址开始
协议：决定每个通信字节的含义
拆分：整数变成字节数组
组合：字节数组恢复成整数
packed：取消填充，但不解决大小端
```

最重要的一句话：

> 通信线路只认识字节；发送端怎样拆，接收端就必须按照相同规则怎样组。
